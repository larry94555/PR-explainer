PR Explainer settings

The model that answers questions in the chat. Explanations, Explain on hover and Explain ahead keep using Model, so a small fast model can explain while a bigger one answers questions. Opening the chat loads it ahead of the first question.

Where Ask a question opens the chat. On the page (the default) floats it over the bottom right of the page. Side panel shows it in Chrome's side panel, next to the PR, so it covers no code and stays open while you move between the PR's tabs; it follows the PR in the tab you are on. Both show the line number and the code you clicked at the top of the chat.

Lower gives steadier explanations; higher gives more varied ones.

Shorter answers arrive sooner. An explanation that reaches this limit is marked as cut off. Chat answers may run to 1024 tokens even when this is lower.

How much the model can read at once, prompt and answer together. Leave empty to size it to each explanation (2048 for most, up to the model's own size or 4096), which is faster and uses less memory. Long code is trimmed to fit.

How long Ollama keeps the model in memory after each explanation, so the next click does not wait for it to load. Opening a PR's Files changed tab also loads it ahead of the first click. 0 frees the memory after each answer and turns that off.

Starts explaining a line when the pointer rests on it for the Hover wait, so a click often shows the answer at once. Only one line is explained at a time, and moving to another line stops it. Nothing is sent while the model is still loading, while the tab is hidden, or on battery when background work is paused.

How long the pointer rests on a line before Explain on hover starts, from 150 to 2000 milliseconds. Shorter starts sooner but sends more requests that are stopped when you move on; the debug window counts those.

When a PR's Files changed tab has been left alone for 2 seconds, explains changed lines before you click them, so a click is answered at once from the cache. Lines on screen explains the lines you can see, at most 30 lines per page. Whole PR works through every changed line of the PR, starting with the code on screen, then the files next to it, then the rest, at most 500 lines per PR in each tab and again after a new commit. Both wait while you click or chat and while the tab is hidden. Off by default because it keeps the model busy and uses battery.

How many explanations are sent to Ollama together. More than 1 only helps when Ollama is set to run several (OLLAMA_NUM_PARALLEL), and usually only on a GPU: on a CPU each answer gets slower and a click waits longer. A click always goes first.

What Explain on hover and Explain ahead do while the laptop runs on battery. Pause sends nothing new until it is plugged in again, and lets an explanation already running finish; the toolbar icon shows ⏸ meanwhile. Keep going never pauses. Your own clicks and chat questions always run.

Files Explain ahead leaves alone, one pattern per line, as in .gitignore: *.min.js matches in any folder, dist/ a folder anywhere, and !keep.min.js keeps a file a pattern above skips. Files the repository's .gitattributes marks linguist-generated or linguist-vendored are skipped too. Hovering or clicking a line in one still explains it.

Lets a reasoning model, such as deepseek-r1, think before it answers. Off by default: without thinking it answers much sooner, and a few lines of code rarely need it. Other models are not affected.

Shows explanations and chat answers word by word while the model writes them. Off by default: the answer appears whole once it is ready, so the sections do not jump around as they fill in.

Keeps explanations on this computer after Chrome closes, so a PR explained once is still instant the next day. An answer not used for this many days is removed, and at most 50 MB is kept. 0 keeps them only until Chrome closes.

Ratings

The 👍 and 👎 you give answers, kept only on this computer: the model, the kind of answer, its length and time, never the code or the answer itself.

The Speed test shows how often each model's answers were liked. Export ratings saves them as a file that npm run bench -- --ratings <file> adds to its report.

Debug

Opens the popup's Details on the explanation's round trip, with the prompt sent to the model and its reply.

Keeps every request to GitHub and to the model (prompt, reply and time) in a log for the debug window. The log is kept in memory on this computer, holds the last 200 requests, and is cleared when Chrome closes or when you turn this off.

Keyboard shortcuts

Opens Chrome's shortcuts page, where these keys can be changed. Explain was Alt+E before, and can be set to Alt+E again there; Chrome only refuses to give it Alt+E by itself, since that key opens Chrome's menu on Windows and Linux. Explain works on the line that has keyboard focus or holds the text cursor, or on the selected lines. You can also right-click a line or a selection on a PR and choose Explain with PR Explainer.

Speed

Times one short explanation on each installed coding model, with the settings above (including Context size, which changes how much fits on the GPU), and marks the fastest one that answers in under 2 seconds. The size of the model and whether it runs on the GPU make the biggest difference. Liked is the share of the model's rated answers you gave 👍, with the number of ratings in brackets (a dash under 10), and below it the same for one line (click, hover or Explain ahead), a whole hunk and the chat.
